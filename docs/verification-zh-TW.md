# 批准與通知驗證

請從自己部署的 HTTPS 網址安裝並開啟 PWA。使用測試用 Bot；不要把實際危險操作當作批准測試。

## 工作狀態

0.1.3 不包含任務／排程工作卡。目前 Bot API 未提供結構化任務清單。普通回合只顯示工作中動畫；真正批准請求才顯示批准卡。

## 批准卡

使用本地 Hermes 原本會要求批准的無害操作，或它已有的批准測試功能。僅要求模型「請先問我」不一定會觸發系統批准；模型輸出的文字詢問不算批准卡。

- 確認卡片列出後端提供的內容、指令詳情與選項。
- 第一輪選「拒絕」，確認 Hermes 沒執行該動作。
- 第二輪選「批准這一次」，確認 Hermes 收到批准並繼續。
- 另一裝置同時打開卡片：已批准或過期卡不可再次執行。
- 不選永久允許，不修改 Hermes 安全策略來強迫測試通過。

## 通知

1. 在 PWA 設定啟用通知並允許系統權限。
2. 按「測試通知」，確認手機系統實際出現通知；「已送出」只代表請求成功。
3. 發送工作後切到手機桌面，確認完成通知實際到達。
4. 觸發真實待批准操作後切到桌面，確認批准通知實際到達。
5. 點通知，確認回到正確 Bot 與對話。

測試通知、完成通知、批准通知必須分別記錄。伺服器已訂閱或 API 回 200 不代表手機已收到。

## AIOT 本機通知服務

通知由 AIOT 啟動程式內的服務接收 Hermes 現有事件，再透過瀏覽器 Web Push 發送；不需修改 Hermes。啟動電腦上的 AIOT，在手機 HTTPS PWA 的「設定 → 開啟通知」允許系統提示，再按「測試通知」。確認通知實際出現在系統通知欄後，再測試 Bot 完成回覆和批准事件。主機必須持續運行 AIOT 且可連到 Hermes 與瀏覽器推播服務。

AIOT 會自動建立加密的 `.aiot/push-private.json`，包含推播私鑰、裝置訂閱及背景連線所需憑證。內容使用 AES-256-GCM；macOS 優先把加密金鑰放在登入鑰匙圈，無法使用鑰匙圈時才以另一個權限為 0600 的本機 `push-state.key` 保存。這些檔案只留在部署電腦，**不得上傳或打包 `.aiot` 目錄**。新使用者會產生自己的金鑰。首次啟用跳過舊事件，斷線後依事件游標接續，短暫發送失敗會重試。通知僅含一般提醒，不含聊天或批准指令內容。
